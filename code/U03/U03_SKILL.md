# U03 倉儲搬運車調度中心技能包

## 你要做的事
使用者是中學老師，不會寫程式。你負責：寫好 Godot 專案 → 自己驗證 → 匯出網頁版 → 用白話回報。做不到的事直接說原因。

## 一定要遵守的規範
1. **Godot 4.7、只用 GDScript**，不用 C#、不裝外掛、不下載素材。3D 物件全用內建形狀（BoxMesh、CylinderMesh…）組合。
2. 場景用程式建立：`main.tscn` 只放根節點掛 `main.gd`。程式分成 `main.gd`、`warehouse.gd`（地圖與 3D 場景）、`fleet.gd`（車隊與調度）、`planner.gd`（找路）、`hud.gd`（看板），每個檔都要有中文註解。
3. **調度的核心（教學重點，要自己寫）**：
   - 地圖是格子；搬運車一次走一格，時間也切成一格一格（tick）。
   - `planner.gd`：時間－空間 A*。每台車規劃時，要避開「別台車已預約的（格子, 時間）」，也要避免兩台車在同一個 tick 互換位置（對撞）。找不到路時可以原地等待（wait 也是一步）。
   - 「協調模式 關」：每台車只用一般 A* 各走各的，不預約；兩台車擠到同一格就算一次「碰撞」（車子閃紅光、暫停 2 秒），讓學生看到沒有調度會發生什麼事。
   - **即時重規劃**：倉庫裡有一個「人員推車」（黃色）會在某條走道來回走；搬運車下一步被它擋住時，要當場重新規劃，並把「重新規劃次數」加 1、在車頭上方冒出「🔄」。
4. **訂單流程**：訂單隨機出現在某個貨架（貨架亮起橘色）；最近而且空閒的車接單（車頂顯示訂單號）→ 開到貨架旁的取貨點 → 取貨（車上多一個箱子）→ 送到出貨口 → 完成。
5. **畫面（亮點）**：
   - 斜上方 45° 的正交（Orthographic）3D 鏡頭看整個倉庫；地板有格線，走道淺色、貨架深藍、出貨口綠色、充電區灰色。
   - 每台車不同顏色、有車號；預約的路線用同色半透明小方塊畫在地上（看得到每台車「打算怎麼走」）。
   - 右側看板：完成訂單、平均送達秒數、等待次數、重新規劃次數、碰撞次數、每台車狀態（空閒／取貨中／送貨中／充電中可省略）。
   - 上方按鈕（滑鼠與觸控都能按）：「開始／暫停」「協調模式 開／關」「速度 ×1／×2／×4」「加一台車」「減一台車」「重來」。
6. **能讓使用者改的東西全放設定檔**（欄位見 `references/設定檔說明.md`）：`warehouse.txt`、`fleet.json`、`orders.json`、`sim.json`。讀不到時用預設值並在左下角用中文提示，不可當掉。
7. 中文字型：`assets/fonts/NotoSansTC-Common.ttf` 複製到專案 `fonts/`，建 Theme 設成預設字型。
8. `project.godot` 設 `renderer/rendering_method="gl_compatibility"`；視窗 1600×900、`canvas_items`、手機直式時看板移到下方。
9. **示範模式** `-- --demo`：自動開始、速度 ×2；前 25 秒「協調模式 開」，接著自動切「關」15 秒讓大家看到碰撞，再切回「開」，畫面上方顯示目前的模式與一句說明。
10. **自我測試** `-- --self-test`（不開視窗）：用 `sim.json` 的種子跑 600 個 tick：協調模式開時碰撞必須是 0、完成訂單 ≥ 10、每台車路線不穿牆；推車擋路時至少發生 1 次重新規劃；最後印 `SELF_TEST PASS …（完成 N 張、碰撞 0、重新規劃 M 次）` 或 `SELF_TEST FAIL 原因`。

## 測試時不可以發出聲音
開視窗測試一律加 `--audio-driver Dummy`。本專案不需要音效。

## 驗證／匯出／Godot 位置
同其他單元：`scripts\檢查.ps1 -Project .`（要「全部通過」）、`scripts\匯出網頁版.ps1 -Project .`；Godot 在練習資料夾旁邊的 `..\Godot\`。`開始玩.bat`、`示範模式.bat`、`export_presets.cfg` 複製到專案。
